---
title: 'Implementation practice'
description: >-
  Give the model context deliberately, keep each task scoped to one coherent change, write
  tests before the generated code rather than after, and read the diff instead of the
  AI-written summary.
order: 2
cardBadges: ['TDD', 'Context Engineering']
---

**Give context deliberately.** A model's output quality tracks the quality of
the context far more than the cleverness of the prompt. A project context file
holding architecture, conventions, module layout and non-negotiables is worth
more than any prompt technique.

**Keep tasks scoped.** One coherent change per session. A model asked to do six
things does five well and one silently wrong, and the one is hard to find.

**Tests before generated code, not after.** If the test exists first, the
generated implementation is verifiable in seconds. If it comes after, you are
writing tests that agree with whatever the model produced — including its
misunderstandings.

**Read the diff, not the summary.** The summary is generated by the same system
that wrote the code. Reviewing the summary is reviewing the model's opinion of
itself.

**Reject early.** The cost of regenerating is close to zero. Arguing with a bad
draft through five rounds of correction costs more than starting again with a
better specification.
